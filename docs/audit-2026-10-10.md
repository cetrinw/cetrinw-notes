## 一、总体评价

**架构**：本地优先、单表 `records(kind, data JSON)` + FTS5 + 每次写入落 `history` 快照的设计简洁一致；同步协议（outbox / receipts / remote_versions）有幂等回执与冲突副本，核心 6 个 Rust 测试覆盖了真实的离线冲突、备份校验和删除不复活场景，质量高于同类个人项目。

**安全基线**：优于预期。
- 服务器 SSRF 防护完整（仅 HTTPS、DNS 解析后拒绝私网/环回/链路本地/IPv4-mapped、`resolve_to_addrs` 固定地址、禁止重定向、流式限长）。
- 令牌比较做了 SHA-256 后常量时间比较；非环回监听强制 ≥32 字符令牌。
- 附件以 SHA-256 命名并在读取时 `safe_hash` 校验，无路径穿越；备份导入逐个校验哈希。
- 前端**没有任何** `dangerouslySetInnerHTML` / `eval` / `localStorage`；RSS/新闻正文在 Rust 侧用 `scraper` 提取纯文本后再入库。
- WebDAV 用 `roxmltree`（不解析 DTD，无 XXE）、`If-None-Match: *` 防覆盖、文件名白名单。

**主要短板**（按影响排序）：
1. **历史表无界增长**（P0，性能/存储）—— 每次 RSS/新闻刷新对每篇文章都 `save()`，即使内容完全未变，也会写新 revision + 全量 JSON 快照 + FTS 重建索引。
2. **课程时间轴校准可静默丢失**（P1，数据丢失）。
3. **`write_export` 接受渲染层任意路径**（P1，纵深防御）。
4. 对话框无 Esc / 焦点管理、全站焦点环几乎缺失、无深色模式与减少动效（P2，可用性/无障碍）。
5. 测试覆盖只到 core + 1 个前端 lib，server/learning/cloud 与 UI 均无自动化测试（P2，工程）。

### D. 功能缺口（相对 README 宣称与合理预期）

1. **回收站**：删除仅打 `deleted=1`，但没有任何 UI 列出或恢复已删除记录（历史已保留，缺的只是视图）。
2. **冲突合并**：冲突副本以独立笔记出现（带「冲突」徽标），没有并排对比/一键采纳。
3. **标签浏览**：标签不可点击筛选；没有标签云/侧栏。
4. **全库 Markdown 导出**：只有单篇 ZIP 与整库 JSON，缺「所有笔记 → 文件夹结构 Markdown」。
5. **研究**：对象（entity）无详情页；关系只有列表无图；数据表字段/类型用 `prompt` 创建。
6. **英语**：无课程删除；无批量下载；TXT 课程时间轴只能手工逐句校准，缺「按音频长度等分」或「以句长比例分配」的一键初始化。
7. **订阅**：摘要型 RSS 没有「抓取全文」（阅读模式）；无全部已读；订阅无图标/网站名自动补全。
8. **同步**：README 提到「换服务器需重新配对」但设置页没有「清除同步状态」操作。
9. **测试**：server/learning/cloud 三个 crate 0 测试；UI 0 自动化；`scripts/*.py` 依赖手工运行且写 `output/`。
10. **可观测性**：Tauri 侧自动备份失败只 `eprintln!`，用户无感知；建议写入 `settings.backup_error` 并在设置页展示。

### E. 性能

- E1 = B1/B4（历史膨胀）是唯一会随时间恶化的问题。
- E2 `useEntries` 对每个 `cetrinw-change` 全量重拉；Today 页同时挂 6 个列表；`MetricView` 每个节点各自监听并重拉。建议改为按 `kind` 维度的共享 store（或 TanStack Query）。
- E3 `Editor.tsx:245-249` 每次渲染对所有已加载笔记 `JSON.stringify`。
- E4 `Chart.tsx` 每次 props 变化 `dispose()` + `init()`；应复用实例只 `setOption`。
- E5 `export()` 把全部附件 base64 驻留内存（250 MB 上限由此而来）。
